# Starter code review

The findings below were checked against the starter implementation and the API contract in `openapi.yaml`. Related failures are grouped where they share the same code path.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` | The endpoint returned success without checking MongoDB, so it could report ready while the database was down. | Stop MongoDB and call `GET /health`; the starter still returned `200`. | Ping MongoDB and return `503` when the ping raises a PyMongo error. |
| 2 | `compute_late_minutes()` | The shift start was built by replacing the punch-in clock time without deriving the correct IST attendance day; overnight punches before shift end can belong to the previous shift-start day. | For a 22:00–06:00 shift, compare a 05:30 IST punch-in against the prior day's 22:00 start. | Derive the attendance date using IST/overnight rules, then build the shift-start instant from that date and compute lateness after the 10-minute grace. |
| 3 | `compute_work_hours()` | Built-in `round()` uses ties-to-even behavior and floating-point arithmetic, not the specified decimal half-up rule. | Exercise a duration whose hour value is exactly halfway at two decimal places; it can round down where half-up requires rounding up. | Calculate from whole seconds with `Decimal` and `ROUND_HALF_UP` to two decimal places. |
| 4 | `compute_overtime()` | It placed the shift end on the attendance date even for overnight shifts and returned any positive overtime, including less than 30 minutes. | For a 22:00–06:00 shift, punch out at 06:20 should yield zero, and at 06:30 should yield 30 minutes. | Place overnight shift end on the next day, calculate whole elapsed minutes, and return zero below the 30-minute threshold. |
| 5 | `create_employee()` and startup indexes | A pre-insert duplicate lookup is subject to a race; without a unique database index, concurrent requests can create duplicate `emp_code` values. | Send simultaneous requests creating the same employee code. | Create a unique `employees.emp_code` index at startup and translate MongoDB duplicate-key errors to `409`. |
| 6 | `EmployeeIn` | The request model did not enforce the OpenAPI employee-code, name, email, department, shift-time, joined-date, and different-shift-time constraints. | Submit a malformed employee code or email, an impossible date, an invalid time, or identical shift times. | Add constrained Pydantic fields and validators, including parsing `joined_on` as a real calendar date. |
| 7 | `create_employee()` | `datetime.now()` created a naive `created_at`, making the stored instant dependent on an implicit timezone convention. | Inspect the inserted BSON date or compare its value on a machine configured for a non-UTC timezone. | Store a UTC-aware, whole-second timestamp created by the server. |
| 8 | `list_employees()` | The total was counted across the full collection rather than the department-filtered query, and the results were not sorted by `emp_code`. | Filter by a department with fewer employees than the collection and compare `total`; seed out-of-order codes and inspect the page order. | Use the same filtered query for `count_documents()` and `find()`, and sort by `emp_code` ascending before pagination. |
| 9 | `list_employees()` and `list_attendance()` | Pagination parameters did not enforce `page >= 1` and `1 <= page_size <= 100`. | Call either endpoint with page zero, page size zero, or page size 101. | Apply FastAPI `Query` constraints to the pagination parameters. |
| 10 | `punch_in()` | An unknown `emp_code` was not handled before accessing the employee record, leading to a server error instead of `404`. | Punch in with an employee code absent from `employees`. | Check the employee lookup and return `404` before using its shift fields. |
| 11 | `punch_in()` | `datetime.fromtimestamp()` and naive `datetime.now()` used the host's local timezone, and the attendance date was not derived from the IST overnight-shift rule. | Run on a non-IST machine or punch in after midnight during an overnight shift. | Convert epoch milliseconds to UTC, convert the instant to IST for the attendance date, then apply overnight handling. |
| 12 | `punch_in()` and startup indexes | Checking for an existing attendance document before insertion cannot prevent concurrent duplicate punches. | Send simultaneous punch-in requests for the same employee and attendance date. | Enforce a unique `(emp_code, date)` index and catch duplicate-key errors to return `409`. |
| 13 | `PunchInIn` and `list_attendance()` | Timestamp and status inputs were not sufficiently strict: non-integer timestamps, out-of-range values, or statuses outside the endpoint's allowed values could be accepted. | Submit a float, string, seconds-looking timestamp, out-of-range timestamp, or invalid status. | Validate punch timestamps as bounded `StrictInt` epoch milliseconds and constrain punch-in and attendance-list statuses to their documented values. |
| 14 | `list_attendance()` | It loaded every matching document into Python and sorted the entire result set there, which does not scale to the required dataset size. | Inspect the implementation or run it against a large collection and observe memory/time growth. | Apply filters, count, sort, skip, and limit in MongoDB. |
| 15 | `list_attendance()` | It returned an extra `id` field and left legacy optional fields absent; response datetimes, including nested history values, were not consistently normalized to epoch milliseconds. | Inspect a response for `_id`/`id`, missing `history`/`half_day`, or BSON datetime values instead of integer milliseconds. | Exclude MongoDB identifiers, fill documented legacy defaults, and convert top-level and nested BSON instants to epoch milliseconds. |
| 16 | `list_attendance()` | Sorting only by date left documents with the same date in unspecified order. | Seed multiple employees on the same date and repeat a paginated query. | Sort by `date` descending and `emp_code` ascending. |
| 17 | `list_attendance()` | Date filters were unvalidated strings, and a reversed `date_from`/`date_to` range was accepted instead of returning `422`. | Call with an impossible calendar date or `date_from` later than `date_to`. | Parse query dates as calendar dates and reject reversed ranges. |

## Investigated, not considered defects

- **Employee pagination offset:** the starter computes `skip = (page - 1) * page_size`, which is the correct offset for one-based pages. The actual listing defects were its unbounded pagination parameters, unfiltered total, and missing sort—not the offset formula itself.
- **Employee `_id` response exposure:** the starter already removed `_id` from the newly created employee response and excluded it from employee listing projections. The employee API did not need a separate `_id` fix.
